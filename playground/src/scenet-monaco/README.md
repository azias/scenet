# `scenet-monaco`

Scenet language support for the [Monaco](https://microsoft.github.io/monaco-editor/)
editor: schema-driven completion, hover documentation and validation for panel and scene
documents, plus syntax highlighting for comic scripts.

## Why this is a directory and not a package

It is written as though it were already published — nothing in here imports from the rest
of the playground, and its only inputs are a Monaco instance and two schema URLs. The
seam is real.

It is not on npm, and that is deliberate. Publishing would mean a second release
pipeline, a second version number, a second changelog, and a public API you have promised
not to break — for a package whose only consumer is the playground three directories up.
That is overhead bought with nothing.

The principle is *design for extraction, extract on demand*. Because the seam exists,
publishing later is mechanical: move this directory, add a `package.json` with
`monaco-editor` and `monaco-yaml` as peer dependencies, and point the playground at the
package instead of the path. Nothing else changes.

If you want it as a package, [say so in an issue](https://github.com/azias/scenet/issues)
— one real consumer is the whole argument.

## What it does

```ts
import * as monaco from "monaco-editor";
import { registerScenetLanguages } from "./scenet-monaco";

registerScenetLanguages(monaco, {
  panelSchemaUrl: new URL("schemas/panel.schema.json", document.baseURI).href,
  sceneSchemaUrl: new URL("schemas/scene.schema.json", document.baseURI).href,
});
```

The schemas are generated by `scenet schema`, from the same pydantic models the compiler
validates against. So the completion list is the language, the hover text is the
docstrings, and neither can drift from what actually compiles.

## The comic-script tokenizer

Comic script carries its structure in line shape, so a Monarch tokenizer — a state
machine over regular expressions, line by line — is the whole implementation. No parser.

Three states: the body, the YAML front matter (delegated to the YAML tokenizer), and
dialogue following a speaker cue.

One rule is worth stating twice, because it is the one that trips people up: **a speaker
cue is recognised by the name being in capitals, not the whole line.** `BOB (whisper)` is
a cue — the parenthetical is lower case and does not disqualify it. The compiler's own
frontend makes the same distinction, and got it wrong the first time.
